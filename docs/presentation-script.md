## 2. 解決したい課題（0:30〜1:30）

【スライド2：課題】
- 旅行の計画は、調べることが多くて時間がかかる
- AIに聞くと、存在しないお店を提案されることがある
- 写真が加工されていて、実際の景色と違うことがある
- 訪日外国人は、日本語の情報だけだと迷ってしまう

> 旅行の計画を立てるとき、観光地、ごはん、宿、移動時間と、調べることがとても多いです。
> 最近はAIに聞く人も増えていますが、AIは**実在しないお店を自信満々に提案してしまう**ことがあります。これを「ハルシネーション」と言います。
> また、SNSやサイトの写真は加工されていることも多く、「実際に行ったら写真と違った」という経験がある人もいると思います。
> さらに、日本を旅行する外国の方にとっては、日本語の情報だけでは計画が難しいという問題もあります。

## 3. TabiAIのコンセプト（1:30〜2:15）

【スライド3：コンセプト「AIの効率 × 実際に行った人の声」】

> そこでTabiAIでは、「**AIの効率**」と「**実際に行った人の声**」を組み合わせて、信頼できる旅行プランを作ることを目指しました。
> 行き先、絶対に行きたい観光地、予算、日数、移動手段、好みを入力するだけで、AIが1日ごとのスケジュールを作ります。
> 日本語・中国語・英語の3つの言語に対応しています。

---

## 4. 主な機能（2:15〜3:15）

【スライド4：5つの機能】
1. AI旅行プラン作成
2. 周辺おすすめ
3. 実際の写真だけを表示
4. 旅行情報の投稿
5. SNSシェア

> 機能は大きく5つあります。
> 1つ目は、条件に合わせて、時間・移動・費用まで入ったプランを作る機能です。
> 2つ目は、メインの観光地の周りにある観光地・グルメ・宿をおすすめする機能です。「ここに行った人は、こんな場所にも行っています」という、ほかのユーザーのルートから集計した情報も出します。
> 3つ目は、写真のルールです。AIで作った画像や加工した写真は使わず、**加工していない実際の写真だけ**を表示します。
> 4つ目は、ユーザーがおすすめのグルメ、コスパのいい宿、実際に回ったルートを投稿できる機能です。この投稿は、AIがプランを作るときの参考データにもなります。
> 5つ目は、プランや投稿を画像にして、SNSでシェアする機能です。

## 6. 技術的な工夫（5:15〜6:30）

【スライド5：使った技術】
Next.js / TypeScript / React / Tailwind CSS / shadcn/ui / Supabase / Claude API / zod / Google Places・Routes・Maps API / next-intl

【スライド6：工夫した点】

> 技術的に工夫した点を3つ紹介します。

> **1つ目は、ハルシネーションを防ぐ仕組みです。**
> AIに自由にスポットを考えさせるのではなく、先にGoogleの地図データから**実在する候補**を集め、AIには「この中からだけ選んでください」と指示しています。
> さらに、AIが返した結果を zod というライブラリでチェックし、候補にないスポットが混ざっていたら作り直させます。
> 最後に、実際の移動時間を計算して、時間が足りなければスポットを減らして調整します。

> **2つ目は、写真とデータの扱いです。**
> Googleの規約では、写真や位置情報を長期間保存することができません。そのため、スポットのIDだけを保存して、表示するたびに取得しています。写真には撮影者のクレジットも表示します。
> SNSでシェアする画像には、他人が撮った写真は使わず、ユーザー自身の写真だけを使うようにしています。

> **3つ目は、データの安全性と、外部サービスなしで動くデモモードです。**
> Supabaseの「行単位のアクセス制御（RLS）」を使って、投稿を編集・削除できるのは本人だけ、などの権限をデータベース側で守っています。
> また、APIキーがなくても動くように、外部サービスの代わりになるモックを作りました。今日のデモは、このデモモードで動かしています。

## 想定される質問と答え

**Q. 普通にChatGPTやClaudeに聞くのと何が違いますか？**
> AIに自由に答えさせるのではなく、実在する候補の中から選ばせて、プログラムでもチェックしているので、存在しない場所が出てきません。また、実際の移動時間で調整していることと、ユーザーの投稿をプランに反映していることが違いです。

**Q. デモで出ているデータは本物ですか？**
> 今はデモモードなので、スポットの名前と位置は実在の場所ですが、5つの地域の一部だけです。投稿はサンプルです。プランもAIではなく、ルールで組み立てています。APIキーを設定すれば、本物のGoogleとAIで動きます。

**Q. 写真が表示されていないのはなぜですか？**
> 「加工していない実際の写真だけを使う」というルールのため、デモモードではダミー画像を使っていません。Googleにつなぐと、Googleの実際の写真と撮影者のクレジットが表示されます。

**Q. お金はどれくらいかかりますか？**
> Google Maps PlatformとClaude APIは、使った分だけ料金がかかります。プランを1回作るたびにAPIを何回か呼ぶので、AIおすすめルートなどの重い機能はログインした人だけが使えるようにしています。

**Q. 一番苦労したところはどこですか？**
> （自分の言葉で答える。例：AIの出力をそのまま信用せず、チェックと調整の仕組みを作ったところ／Googleの規約に合わせたデータの持ち方／デプロイで環境変数がなくてエラーになったところ）

**Q. 外国人の旅行者はどうやって使いますか？**
> 画面の右上で中国語や英語に切り替えられて、プランもその言語で作れます。投稿は「翻訳」ボタンで自分の言語に翻訳できます。
